# What is the Digital Twin?

A digital twin is not a dashboard. It is not a report. It is a **live, accurate, granular model of the real company**.

## What It Maps

- **Departments**: Engineering, Product, Sales, Marketing, Customer Success, Executive, Operations
- **People**: Each person with role, skills, availability, cost/hour, reporting structure, workload capacity
- **Capacity**: Hours/week, cost/hour, bottleneck risk
- **Real-Time Changes**: Updates propagate immediately when mapping is edited via API

## Why It Must Be Granular

A template says "Engineering has 10 people." A true digital twin says:
- Engineering: 10 people
- Head: CTO (reports to CEO)
- Members: 4 Python specialists, 3 distributed systems, 2 ML engineers, 1 security
- Capacity: 640 hours/week at $180/hour
- Skills mapped to project needs
- Real-time workload balance visible in simulation results

## How It Differs From Templates

| Feature | Template ERP | Singularity Digital Twin |
|---------|-------------|-------------------------|
| Department mapping | Static list | Dynamic, API-editable, granular |
| People mapping | Job titles only | Skills, availability, cost, reporting |
| Real-time sync | Batch updates | Continuous ingestion + propagation |
| Simulation input | Manual entry | Direct from live twin state |
| Accuracy | Generic | Accurate, true copy of real organization |

## The Simulation Connection

When launching a product, the twin tells us exactly how many engineers are available, which skills are needed, and how long it will take — then simulates the impact on revenue, deadlines, and NPS.
